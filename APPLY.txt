SIGMA Engine built-in PSA economic-input patch r6
=================================================

Baseline
--------
Apply this overlay to miraflor/sigma-engine at commit:

411ad11d9363837bd58d17aa063a285bc5ad7ad1
Revise SIGMA workflow to v0.1.0 specification

What changes
------------
Normal IO80 and IO16 runs become self-contained.

The package already contains the normalized 2018 PSA intermediate transaction
matrices Z. This overlay adds the corresponding compact gross-output vectors x:

- src/sigma_engine/resources/psa_2018_io80_total_output.csv
- src/sigma_engine/resources/psa_2018_io16_total_output.csv

The default Step-5 path is therefore:

    built-in Z -> MWAS edge selection
    built-in x -> A_ij = Z_ij / x_j -> surviving-edge weights

Neither --transactions nor --technical-coefficients is required for the normal
built-in IO80/IO16 workflow. Both remain explicit custom overrides.

The engine never substitutes the intermediate-input column sum for gross output.

Apply and verify
----------------
Place these two downloaded files in your Downloads folder:

- sigma-engine-builtin-psa-r6.zip
- apply_sigma_engine_builtin_psa_r6.ps1

Then, from the sigma-engine repository in the openplaces-ph environment:

    Unblock-File "$env:USERPROFILE\Downloads\apply_sigma_engine_builtin_psa_r6.ps1"
    & "$env:USERPROFILE\Downloads\apply_sigma_engine_builtin_psa_r6.ps1"

The script requires a clean working tree at the baseline commit, creates a recovery
branch, verifies the ZIP checksum, applies the overlay, runs Ruff/compileall,
runs focused economic-input tests and the full repository test suite, and checks
the CLI's no-external-economic-file default contract.
